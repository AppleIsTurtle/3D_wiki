D'un logiciel à l'autre

  1. Karma ou Redshift écrivent un EXR linéaire, sans vue. Note dans quel espace : Linear Rec.709 pour Karma avec houdini-config, ACEScg pour Redshift par défaut.
  2. Nuke lit l'EXR dans cet espace (Read > Input Transform), compose, puis écrit un EXR, ou une preview avec la vue.
  3. Resolve reçoit l'EXR avec le bon Input Color Space, étalonne, puis sort les livrables SDR et HDR par l'Output Color Space.
  4. Toute l'équipe regarde à travers la même vue, du lighting à l'étalonnage.

Pièges

Houdini

  • Le viewer s'ouvre en Un-tone-mapped : pas de vue ACES par défaut.
  • Avec les réglages par défaut, Redshift rend en ACEScg alors que Houdini et Karma travaillent en Linear Rec.709.
  • Les règles de fichiers de houdini-config rangent les EXR en Linear Rec.709, sauf si le nom contient ACEScg : un EXR en ACEScg mal nommé doit être réglé à la main.

Nuke

  • En 17.x, avec les configs ACES fn-nuke, les fichiers 8 bits passent par le rôle matte_paint = ACEScct : un PNG est mal lu. Foundry le liste comme bug connu (613757) pour les configs 2.x.x ; le même défaut se mesure en v3.0.0, et aussi à l'écriture.
  • Écrire une preview en display puis la relire à travers la vue applique la vue deux fois.
  • Dans Nuke 16, les configs fn-nuke v1.0.0 ont les rôles matte_paint et texture_paint inversés par rapport aux fn-nuke de Nuke 17.

Resolve

  • DaVinci YRGB, le mode par défaut, ne gère pas les espaces : choisis RCM ou ACES.
  • En RCM, l'Input Color Space par défaut est Rec. 709 Gamma 2.4 : un EXR en ACEScg doit recevoir son Input Color Space à la main.
  • Plusieurs fonctions HDR sont réservées à la version Studio ; le manuel et la liste des fonctions ne disent pas tout à fait la même chose.
Pour aller plus loin

Comment ces réglages ont été vérifiés

Houdini 22 et Redshift : valeurs lues dans une scène neuve avec hython, et dans l'aide locale. Nuke 17.1 : knobs lus en mode terminal non commercial, qui ignore les préférences : les défauts d'un nouveau script en interface peuvent différer. Resolve n'était pas installé : tout vient du manuel 21.1 et de la liste des fonctions. Deux points restent à confirmer par un test : la détection Auto des textures de Karma, et la vue par défaut du RenderView de Redshift.
