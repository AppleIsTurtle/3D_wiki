OCIO

OCIO (OpenColorIO) est une bibliothèque libre qui convertit les couleurs pour les logiciels, d'après un fichier de config partagé.

Sans config commune, chaque logiciel lit et affiche les nombres à sa façon : les mêmes fichiers donnent des images différentes. Avec la même config, Houdini, Nuke et Redshift s'accordent sur ce que valent les nombres.

OCIO n'est pas ACES. OCIO est le moteur, la config est le dictionnaire. ACES est une norme ; ses espaces et ses vues existent sous forme de configs OCIO, mais Resolve, par exemple, applique ACES sans OCIO. Une config peut ne contenir aucun ACES : c'est le cas de nuke-default.

Ce que contient une config

  • Des espaces, avec leurs alias (autres noms).
  • Des rôles : des noms génériques que les logiciels utilisent, reliés à un espace réel.
  • Des displays et leurs vues : l'écran cible et le rendu à travers lequel on le regarde.
  • Des looks, et des règles de fichiers qui devinent l'espace d'une image d'après son nom.

Qui choisit la config

La variable d'environnement $OCIO donne le chemin de la config, ou une config intégrée à la bibliothèque (ocio://default). Si la variable n'est pas déjà définie, Houdini 22 la règle lui-même sur houdini-config. Redshift reprend celle de Houdini, mais rend par défaut en ACEScg, pas dans le scene_linear de houdini-config. Nuke se règle dans les Project Settings. Resolve a sa propre gestion des couleurs et n'utilise OCIO que dans quelques effets. Le détail est dans la page Logiciels.

Attention : dans houdini-config, le rôle scene_linear vaut Linear Rec.709 (sRGB), alors que dans les configs ACES courantes il vaut ACEScg. Deux configs « ACES » ne travaillent donc pas forcément dans le même espace.

À retenir

  • OCIO applique les conversions ; la config décrit les espaces, les rôles, les displays et les vues.
  • Toute l'équipe doit utiliser la même config : $OCIO la fixe, ou le réglage du logiciel (Project Settings de Nuke).
  • Les rôles disent à un logiciel où travailler par défaut, mais chacun les interprète à sa façon : Redshift rend en ACEScg quel que soit scene_linear.
  • Les règles de fichiers devinent l'espace d'après le nom : vérifie toujours ce qu'elles ont choisi.

import PyOpenColorIO as OCIO
cfg = OCIO.GetCurrentConfig()          # la config de $OCIO
print(cfg.getRoleColorSpace("scene_linear"))
cpu = cfg.getProcessor("sRGB Encoded Rec.709 (sRGB)", "ACEScg").getDefaultCPUProcessor()
print(cpu.applyRGB([0.5, 0.5, 0.5]))  # gris sRGB 0,5 → ≈ 0,214 en ACEScg

OCIO v1 et v2

En v1, une vue pointait vers un seul espace qui faisait tout. La v2 (2021) sépare la vue en « view transform + espace du display », et ajoute les alias, les règles de fichiers et les shared views ; les configs intégrées arrivent avec la 2.2 (2022). Les anciens noms (Utility - sRGB - Texture…) restent souvent valables comme alias : le décodeur les traduit.

Histoire

OCIO a été créé chez Sony Pictures Imageworks et publié en open source en 2010. Il fait partie de l'Academy Software Foundation depuis 2019. Jeremy Selan a reçu pour son développement un Technical Achievement Award de l'Académie en 2014.
